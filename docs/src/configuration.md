# Configuration

funkalization keeps its state in a repo-local `.funkalization/` directory once
the workspace lands (gate G1). ddl treats `.funkalization/` as the tool's
config dir — no other location is read.

Planned layout (from the design contract, `openspec/design/…/README.md`):

| Path | Contents |
|------|----------|
| `.funkalization/workspace.json` | accepted commitments, proposals, revisions |
| `.funkalization/events/` | M3-style propose / decide / report event log |
| `.funkalization/obligations/` | obligations generated by design decisions |
| `.funkalization/evidence/` | scoped evidence, judgments, counterexamples |
| `.funkalization/views/` | derived diagram/table projections (never authoritative) |

Status dimensions stay orthogonal: **lifecycle** (`proposed`/`accepted`/`superseded`),
**provenance** (`declared`/`derived`/`observed`), and **verification**
(`pass in scope`/`fail`/`unknown`/`unsupported`) are never conflated into one field.
